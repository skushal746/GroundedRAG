Orbitask API Troubleshooting Guide

This guide covers the most common problems developers hit when integrating with the Orbitask REST API v2. The base URL for all requests is https://api.orbitask.example/v2.

Authentication

Every request must send a personal access token in the Authorization header as Bearer <token>. Create tokens under Settings > Developer > API tokens. Personal access tokens expire after 90 days by default; when you create a token you can choose any lifetime between 30 and 365 days. Expired or revoked tokens return 401 invalid_token.

Tokens inherit the permissions of the user who created them. If a token's owner is removed from the workspace, all of their tokens are revoked immediately.

Rate limits

Rate limits are applied per workspace, across all tokens, over a rolling 60-second window.

When you exceed the limit the API responds with 429 rate_limited and a Retry-After header containing the number of seconds to wait. Wait at least that long before retrying, and use exponential backoff with jitter for repeated 429s. Every response also includes X-RateLimit-Remaining so you can slow down before hitting the limit.

Pagination

List endpoints use cursor pagination. Pass limit (default 50, maximum 200) and the next_cursor value from the previous response as cursor. Cursors expire after 10 minutes; restart from the first page if you receive 400 invalid_request with the message "cursor expired".

Webhooks

Webhook deliveries are signed. The X-Orbitask-Signature header contains an HMAC-SHA256 of the raw request body, using your endpoint's signing secret as the key. Always verify it before trusting the payload.

Your endpoint must return a 2xx status within 10 seconds. Failed deliveries are retried up to 8 times over 24 hours with exponential backoff. After the final failed attempt the event is dropped and the webhook is flagged as failing in Settings > Developer > Webhooks. A webhook that fails continuously for 3 days is disabled automatically.

API versions

API v2 is the current version. API v1 is deprecated and will be shut down (sunset) on 31 December 2026; after that date v1 requests return 410 Gone. See the migration guide for field name changes between v1 and v2.
